# ADR-005: 知識領域と文書形式を分けて配置を決める

Date: 2026-09-14。Status: Accepted。Owner: harness-maintainers。

## Context

既存のH00–H26と領域indexは、知識を置く場所を提供するが、収録対象・隣接領域との境界・文書形式の選択基準を示していなかった。分類が網羅されているか、プロジェクトの情報が充足しているかも区別できなかった。利用者はこの不足の解消に加え、AI Agentが意図と異なる配置や仕様の決定をしないことを求めている。

## Decision

H00–H26を知識領域として維持し、文書形式と別の軸として扱う。[配置規約](../harness/documentation-policy.md)で、正本の選択順序、全領域の境界、形式別の作成基準、scopeごとの網羅性点検を定める。

Agentはユーザーの明示指示、既存正本、情報の性質、領域の問い、ownerの順で配置を決める。配置記録と3視点のレビューを要求し、根拠から決まる配置は実行する。未決の業務条件と正本の衝突は推測で解消しない。AGENTS.mdを入口として、導入先へ配布するseedにも共通規約と入口を含める。

## Alternatives and rationale

| 案 | 利点 | 不採用理由／採用境界 |
|---|---|---|
| 領域indexの説明のみ増やす | 変更が小さい | 横断する境界の優先順位とAgentの実行手順が分散する |
| ADR・仕様・Runbookごとのトップレベル分類へ再編する | 形式で探しやすい | 同じ主題の正本が分散し、既存pathとconsumerの移行が発生する |
| H00–H26を維持し、形式・境界・判断手順を追加する | 既存pathとschemaを保ち、配置不能事例を説明できる | 採用。意味上の境界は文章レビューが必要 |
| 全文書の分類と網羅性をCLIの新gateで判定する | 一部の手続き違反を強制できる | 正本や要求の意味の判定は構造検査だけではできない。今回はルールの明文化に限定する |

## Consequences

既存文書の一括移動とinterface/schema変更を伴わず、人とAgentが共通の基準で配置できる。形式として欠けていたRFC、Runbook、調査・会議記録等は、既存領域内に配置できる。

配置理由、owner、正本へのリンクを維持する負担が増える。網羅性は確認したscope・シナリオに限定され、未知の要求がないことは証明しない。Agentが指示に従うことや文章の意味はCLIが保証しないため、判断例によるレビューと既存のknowledge検査を併用する。

既存ファイルは規約の命名例だけを理由に改名しない。既存本文の一斉書き換えも行わず、変更対象から正本・owner・更新契機を整える。プロジェクト固有の採用判断・ADRをseedへ複製しない。

## Review triggers

既存分類へ置けない具体例、繰り返されるAgentの誤配置、正本の衝突、interface/schema変更が発生した時点で見直す。新しい分類や機械gateが必要なら、対象・受入条件・既存consumerへの影響を別Taskで定める。
